## The admin back office

`docs/rules/admin.md` -- 23 rules

- The admin dashboard's information architecture lives in `src/lib/adminNav.ts`
- Every session and every person has a timestamped history, built from what is already recorded rather than a new event table
- People -> Abandoned checkouts is a list of leads, never approvals
- A scope that could not be read is refused, never promoted, and a screen outside the scope never leaves the server
- No password is issued, stored or shown - an admin hands over a one-time link
- User Access is where the access model is read, and it is derived
- Settings is eleven screens under four captions, and the captions are part of the definition
- A settings screen says what it is and gives an example
- System Health is thirteen checks in one shape, and every unhealthy one says how to fix it
- A count links to the rows it counted, never to the whole table
- A session is listed once
- A person's session list is ordered by the session, not by the booking
- Every admin export offers CSV and PDF, from one column definition
- The log is a section of its own, and clearing it is the one thing that takes evidence away
- An audit write is tried twice, and a write that still fails is not lost
- An audit entry is read months later, so it says what changed from what
- A profile change is checked by value, and approving it is claimed before it is applied
- Approvals are a queue, not a person
- Approving and declining a signup cannot both land
- Admin-configurable behavior
- Checkout speed is the one check that measures the product rather than a backlog
- Countries & currency lives under Catalog, because it decides what a patient is charged
- Appearance (Settings -> Public Site) is one switch: follow the device's light/dark setting

## The database, and talking to it

- Session credits are a ledger, not a counter
- An invariant the app enforces belongs in the database too
- A function is revoked from `public`, `anon` AND `authenticated` - all three, every time

- A composite index serves its own prefix

- Every list pages, and every list that has a dimension filters

- A switch that decides nothing is worse than no switch

## Roles, security and operations

- Rate limiting is Postgres, not Redis, and it fails open
- A flag is never an accusation, and never carries a penalty
- The platform keeps its own conversations, and leaves evidence when it doesn't
- Only a patient account can book; one account carries one role
- An admin can sign in as somebody, and that is a session swap rather than a preview
- Don't name the back office to anyone outside it
- The debug bar is on in every environment, on purpose
- The simulated clock moves one server gate, and only behind a server flag
- No `.env` file that arms the reset is committed, and two have been
- `.env.production` stays deleted
- The page behind an intercepted overlay is the dashboard, not a frame that looks like it
- A full-screen overlay opened from inside another one must be portalled
- Every route tree has an error boundary, and a thrown message never reaches the screen
- A display code outlives the role that generated it
- A fallback that is silent is half a fix
- A hardcoded `?section=&tab=` link is a dead link waiting to happen
- The signature is the whole guarantee
- The user id in the payload is the second guarantee
- Only a successful read is cached
- No secret configured means no caching
